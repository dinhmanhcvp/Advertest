1. Executive Summary

Face detectors trained on clean, eye-level photos degrade on wearable-camera footage. AdverTest measures that gap, synthesizes the failure modes with an auditable attack engine, retrains, and accepts the new model only if it passes a blind evaluation gate.

Model: yolov7-face (bounding box + 5 facial landmarks). Base domain: WIDER FACE. Target domain: Ego4D Social (first-person video with fisheye distortion, head-bob motion blur and sensor degradation). The Enterprise Data Platform supplies raw data through short-lived presigned URLs; raw frames are streamed and never persisted on developer machines.

2. Workflow

1 · Triage

Baseline inference; a hard negative is a face with IoU < 0.5 or confidence < 0.4. Only that subset moves on.

2 · Synthesize

Radial distortion, biomechanical IMU blur, sensor degradation, occlusion. Exclusion matrix and a 50% bbox-integrity gate; every sample carries an audit trail.

3 · Retrain

Fine-tune on targeted samples plus a clean replay set (guards the base domain).

4 · Blind gate

Held-out images: accept V2 only if corrupted mAP gains ≥ 5 points and base mAP drops ≤ 1 point.

All heavy compute runs on a Colab GPU worker (colab/colab_zero_disk_pipeline.py); the laptop footprint stays under 5 MB. The web console and API serve the exported results.

Limitations — read before relying on these numbers

  • Target domain is a proxy. No Ego4D footage was used yet (licence keys pending). “Corrupted” means WIDER FACE passed through the physical attack engine, which has exact ground truth. Real Ego4D frames are supported (streamed from presigned URLs) but not yet evaluated.
  • Small sample. 80 blind images and a single run: the corrupted-mAP gain clears the 5-point gate by under one point and has no confidence interval.
  • Modest recovery. 16% of the baseline hard negatives are recovered; most remain failures.
  • Landmarks are pseudo-labels. WIDER FACE has boxes only; training landmarks come from the baseline model, transformed with the same geometry as the image.
  • Model weights live on the Colab worker until exported to the Core Data Lake (see the handover notes).
